# AIGC 视频协作工具

M1 原型：登录/注册、角色入口、多项目、成员角色、集分配、项目总览状态灯、我的集、通知与未读。当前阶段只实现 M1，不包含 M2 的 Word 解析、集快照、diff、docx 导出，也不包含 M3 的资产审核。

## 技术选型

- Monorepo：使用 npm workspaces，`apps/web` 和 `packages/domain` 分离。M1 先用 mock 数据跑通业务路径，后续接 PostgreSQL 时可以复用领域类型与选择器。
- Web：Next.js App Router + React + TypeScript。理由是后续 M2/M3 会需要服务端路由、文件上传、导出任务和权限过滤；App Router 可以逐步接入 Server Components、Route Handlers 和 Server Actions。
- 领域层：`packages/domain` 保存 M1 类型、seed 数据、注册/登录、权限、状态变更函数和选择器。这样 UI 不直接硬编码业务规则。
- 测试：Vitest 覆盖 M1 领域行为，包括注册登录、项目 CRUD、成员角色、集分配、我的集、状态灯、未读通知和角色权限。
- UI：纯 CSS + lucide-react 图标。M1 是工作台型产品，优先清晰身份入口、信息密度、状态可扫读和权限边界。

## M1 当前岗位权限

这是 M1 的合理默认，后续可按你的确认继续细化：

- 项目所有者：拥有全部项目管理权限，M1 中等同最高级统筹。
- 统筹：可创建、编辑、归档项目；可添加成员并设置岗位；可给成员分配负责集；可看项目总览、所有状态灯、我的集和通知。
- 主编剧：可看项目总览和所有集状态；后续 M2 可发布交稿包；M1 不可管理项目、成员和集分配。
- 编剧：可看项目上下文；可被分配“编剧负责”的集；后续 M2 可参与交稿与反馈；M1 不可管理项目、成员和集分配。
- 创作者：只看自己被分配的集、未读通知和待处理提示；不显示项目管理、成员管理、集分配入口。

M1 已把两个概念拆开：

- 成员与角色：只回答“这个人是不是项目成员、可以同时是什么岗位”。
- 权限分配：保存成员身份后，可对该成员单独勾选项目管理、成员管理、集数分配、总览查看等权限。
- 集分配：只回答“这个成员负责哪几集、以什么分工负责”，例如“编剧负责”“主制作”“创作者制作”“审阅负责”。

## 本地启动

```bash
npm install
npm run dev
```

打开终端输出中的地址，通常是：

```text
http://localhost:3000
```

如需固定监听地址和端口：

```bash
npm run dev -- --hostname 127.0.0.1 --port 3000
```

## M1 验收步骤

1. 打开首页，先看到登录 / 注册页，而不是直接进入工作台。
2. 在登录页选择“陈统筹 · 统筹”，点击“进入协作台”。
3. 统筹进入后能看到项目总览状态灯、项目管理、成员与角色、集分配、我的集和未读通知。
4. 退出登录，选择“沈制作 A · 创作者”登录。
5. 创作者进入后只看到自己的集、未读通知和提示，不再显示项目管理、成员与角色、集分配。
6. 退出登录，切到注册，输入名称 `linyu`，角色选“创作者”，点击“注册并进入”。
7. 新注册创作者进入后能看到空的“我的集”，提示需要统筹分配后才会出现负责集。
8. 用统筹账号登录，在“项目管理”里创建一个新项目，项目会出现在左侧导航与项目列表中。
9. 统筹点击项目列表里的编辑按钮，修改项目名并保存。
10. 统筹在“成员与角色”里选择成员和一个或多个角色，保存后成员计数会更新；这里不再填写集范围。
11. 统筹在“成员与角色”的权限分配里选择已保存成员，勾选权限并保存。
12. 统筹在“集分配”里选择项目成员、分工类型、起始集和结束集，项目总览状态灯会显示负责人。
13. 点击未读通知的勾选按钮，未读数量会减少。

## M1 边界

- 登录/注册是 mock，数据保存在浏览器内存，刷新后恢复 seed 数据。
- 权限是前端原型层的 M1 默认规则，还不是生产级鉴权。
- M1 不上传 Word，不生成交稿包，不生成集快照。
- M1 不做资产候选、缩略图和定稿下载。
- M1 页面已预留后续“项目总览 / 我的集 / 通知 / 分配”的信息架构，但不会提前实现 M2/M3。
